# 第三十九阶段：根据证据选择下一步，换一种方式解释

日期：2026-11-12（Asia/Shanghai）。继续升级光光、力力的实验辅导，完成本地代码、回归检查及生产构建。腾讯云配置按用户要求保持暂停。

## 本轮可体验的变化

1. **根据当前条件决定下一步。** 两位助手增加“下一步做什么／帮我规划下一步”。先处理当前页面的阻碍，再根据本轮操作、观察或具体采样给出一个动作与观察目标。短追问“下一步呢”也走当前状态辅导；“再给一点提示”才递进提示级别，没有前文的短追问仍会澄清。
2. **检查记录里缺什么。** 力力新增“检查我的记录”，区分页面声称的条数与实际收到的记录。自动模型采样按原条件重算，区分同条件分组与不同横坐标；重复保存同一点不等于获得更多独立取值。混合自动模型和手动虚拟读数时先让学生选来源。单摆、双缝、纸带的手动记录保留原始量与保存时条件，下一步检查计数、定位、零点等，不根据模型答案倒填数据。
3. **没听懂时换讲法。** “没看懂／换个说法”按近期话题提供通俗解释、小观察或概念区分。光光可轮换表达方式，力力覆盖控制变量、图像、手动读数、误差与当前状态；未知话题不硬猜。新解释仍先核对当前装置提示。
4. **纠正错误的学习证据判断。** 光光本轮画像、长期记录和主动建议统一使用学生本人表达的结构线索；助手讲过、学生点过按钮都不代表学生已经解释或掌握。去掉界面中容易误解的“可信度”百分比，改为练习线索。结构检查只检查是否包含证据、因果、条件，不能认证物理结论正确。
5. **实验回访重新建立讨论。** 力力保留旧回答及原条件作为显示历史，但新的访问不取旧话题、旧建议或旧提示级别。A→B→A 即使发生在两次渲染之间，也会隔离访次并取消旧请求；同实验改参数仍保留讨论，旧回答继续标注原条件。

## 数据与判断边界

- 光光读取页面快照、操作与学生文字，力力读取当前参数、模型采样和支持的手动虚拟读数；均不是摄像头识别。没有收到具体记录时明确说明，不把条数当证据。
- 光光 API 将客户端状态摘要与教学检索资料分开，保留控件、装置、页面读数、模型推导的来源。即使 `ready=true`，存在待处理页面提醒也优先处理；不采用其他实验的当前／上一快照。
- 历史助手回复仅帮助选话题或表达方式，不能代替当前读数或证明学生完成过操作。学生记录的原文也不是已被系统独立核验的实测结果。
- 本地学习历史仍保留既有设备／领域存储范围，没有在这轮完成全部历史的账号迁移。练习线索与对照轨迹不等于掌握度或已经验证的公平对照。
- 新增检查、下一步和简化解释采用有边界的本地辅导，普通问题沿用既有在线／回退链路；没有新增或启用模型供应商，也未调用付费模型。不能把这些改动表述为任意自然语言理解已经验收。
