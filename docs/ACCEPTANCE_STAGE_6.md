# 第六阶段：可靠的检查流程与手动操作边界

日期：2026-11-11。代码仍在本地工作区，未推送、部署或调用付费AI。

## 开发质量流程

新增PR/手动质量工作流；原有主分支Pages流程改为完整检查通过后才能上传站点与部署。检查包括类型、全部包测试、知识检索、架构和生产资源预算。PR及构建只读代码，部署权限限于独立部署任务。官方action版本固定提交SHA，日志仅上传明确列出的检查报告，保留7天。

本地checkpoint原先只向npm父进程发送终止信号，后代进程可能继续占用输出管道。现在macOS/Linux为单阶段创建独立进程组，取消/超时先终止整组，2秒后强制结束；每阶段默认10分钟。退出前刷新日志、记录失败原因并释放锁。锁写入失败、阶段命令无法启动和报告写入异常也经过清理路径。断电/系统强杀仍需确认进程后处理遗留锁。

增加真实子进程回归：成功与非零退出、缺失命令、预先取消、超时、父进程拒绝退出、父进程退出但重定向输出的子进程仍存活、日志打不开，以及检查协调器的四阶段顺序、失败停止、锁竞争和取消。Linux另有 `/dev/full` 日志写入失败用例，在macOS上跳过；Windows任务树行为未实机验收。

## 后端测试隔离

原来的API通用fixture只设内存数据库路径，仍可能优先使用继承的 `DATABASE_URL`。现显式清空数据库URL、固定内存SQLite、显式设置演示种子并禁用真实AI/vector配置。生产初始化测试仍只创建配置的管理员。回归用独立子进程注入不可连接的假数据库地址和假部署环境，验证不会读写外部库或调用供应商。

## 手动实验交互

- 双缝原先按结果对象引用判断是否已保存，数值不变的失焦重算也会再次允许存档。现在按原始读数与完整条件判断本轮记录，修改后恢复原值或暂时清空输入再恢复也不会重复存档。
- 档案清空后可以重新保存；独立的重复实验可以保留相同结果。单摆重新开始计时、双缝点击“开始下一次读尺”均开启新一轮观察。
- 单摆在零时刻开始手动计时后，点击“重新计时”即使时间值仍为零，也会作废未完成计时。显式重置标识由高中页面管理，暂停/单步不会作废，已保存历史保留，共享时钟不受影响。
