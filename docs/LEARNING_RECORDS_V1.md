# 学生实验档案：保存与身份边界

班级任务中的“学生填写记录 → 后台保存 → 任课教师查看”使用统一四段文字报告。最初以凸透镜任务验收，第十四阶段已覆盖7项开放高中实验，第十五阶段补齐课堂缓存与事件队列的后台、学校和学生隔离。原有自由探索记录本继续独立使用。更新日期：2026-11-11。

## 体验流程

1. 启动带后台的开发环境：在工程根目录运行 `npm run start:platform -- --with-api`。
2. 教师登录，创建班级实验任务并发布；学生从学生空间的任务中心进入实验。
3. 点击实验顶部的“填写实验记录”，填写预测、测量数据与观察、结论与依据、疑问。
4. 等待状态变为“已保存到账号”。返回任务中心点击“完成并归档”；系统先检查并同步本页草稿和该会话的初中操作队列。若另有标签页草稿，需要先核对并再次确认，流程见下文。
5. 教师进入“报告”页面，选择班级与任务，展开学生的实验档案。
6. 在该档案中打开“查看与编写教师反馈”，核对四段原文与版本，再提交具体建议。报告若已更新，先刷新并明确重新核对；网络结果不明时沿用原提交重试。
7. 学生在同一报告页点击“读取教师反馈”，可展开所评版本的四段原文。进行中的报告仍由学生自行修改保存；已完成报告保持只读，不因反馈重新开启实验。

开发账号见 [后台说明](../apps/api/README.md)。正式账号模式需要运行 API；静态演示网页不会自动拥有这些后台能力。

学生记录路由：`/#/student/records/:sessionId`；教师查看路由：`/#/teacher/reports`。学生历史实验卡片也有“查看实验记录”入口。

## 保存行为

- 输入先暂存浏览器，再自动上传；“已存本机 · 待同步”和“已保存到账号”分别显示。
- 网络失败会保留当前标签页草稿，联网后或点击重试可继续上传。未同步时应保留当前标签页；同步成功后可登录同一账号读取。
- 重试使用原操作编号，服务端避免重复写入。正常的新编辑使用新的操作编号。
- 两处编辑发生版本冲突时，页面保留本机草稿并显示账号中的记录，由学生选择保留自己的内容或采用账号版本。
- 页面以学生实际看过的版本作为修改基准，避免另一个标签页更新后被旧页面静默覆盖。
- 已完成的实验只读，服务端同样拒绝修改。完成只表示结束这次实验，不代表教师已评价结论。
- 学生只可读写本人记录；教师只可查看自己创建班级下的记录；管理员可查看本校记录。
- 浏览器存储写入失败时不显示保存成功；尚未落盘的文字保留在当前页面的内存副本中，可明确查看、导出及恢复，边界见下文。

## 当前身份与本机缓存

报告页、任务中心及初中课堂自动同步固定使用学生登录通道。它们不跟随高中原始档案选择器切换到教师或游客，也不借用教师令牌。高中读数选择器仍独立核对其来源档案是否属于这份报告的学生。

`studentRecordScope` 用后台 API 命名空间、学校 ID、学生 ID 选择缓存，并用修订号区分当前登录状态。同账号续期保留缓存键，但旧回调失效；切换学生、学校、后台、退出或到期后，读写、请求回包、冲突处理与导出会重新检查捕获的身份。

本机解析令牌 payload **只用于选择缓存和界面状态**，没有替代服务端验签、账号状态及班级/会话权限检查。服务端仍负责真实鉴权。过期的原学生身份可以只读查看、导出该身份的本机副本，不再编辑、同步、开始或完成任务；退出、无效身份和演示模式不会读取某个学生的课堂缓存。

新报告缓存使用 `physics-learning-record-v3`，在身份键下区分会话和页面草稿；活动会话和初中事件队列也使用各自的 v3 身份键。每次页面生命周期生成新的随机草稿编号，不沿用可能被复制标签页继承的 `sessionStorage` 编号。同一页面内切换路由保留编号；刷新或新开页面使用新编号，刷新前已写入本机的草稿作为“其他页面草稿”保留，需要明确恢复，**不会刷新后自动接管**。

旧 v2 报告不自动迁移，旧全局活动会话与事件队列保留原位，不被新流程读取或补传。

## 旧副本与异常副本

报告页面的副本面板只在明确点击查看后扫描，挂载时不读取副本正文；查看、下载均再次核对身份与当前会话。

- **升级前的本机副本**：只匹配当前学生 ID、当前会话的旧 v2 键。旧键没有后台地址，学校字段也不能证明它属于当前后台，因此始终标为未验证来源。所有标签页草稿分别保留，包括没有对应旧账号缓存的草稿；不只挑当前标签页，不上传、合并、删除或补写。
- **其他页面草稿与异常副本**：只读取当前 v3 身份和会话下的其他标签页草稿。正常的本页草稿仍在报告编辑器中；本页损坏草稿及损坏或身份不符的本机账号缓存提供原文备份入口，不能当作正常报告。
- JSON 保留预览时读到的完整原文，不按报告字段长度截断。旧 v2 备份另外保留原键、读取时间和来源边界。损坏 JSON 仍可作为原文备份；内容本身无法读取时会明确提示不完整，不能声称已经备份了未读到的字节。
- 导出不等于保存到账号，也不会解决版本冲突。原标签页还可能继续编辑，文件只是预览时的副本；身份或会话变化、卸载后的旧下载回调不会继续发起下载。

## 未落盘正文与明确恢复

本机存储满额或写入失败时，编辑器先保留四段完整文字及其原账号版本号。内存副本按后台、学校、学生、会话隔离，当前页面内的路由切换、登录到期、续期和组件重新挂载不会删除它；其他账号不可见。它没有写入磁盘，也不跨标签共享，**刷新或关闭页面可能丢失**。页面注册离开提醒，但不能保证浏览器总会显示，因此应先展开“未落盘正文”并导出 JSON。

有效的其他页面草稿、未落盘内存正文均可在完整预览后，明确选择“恢复这份页面草稿”或“恢复这份文字为草稿”。恢复会替换当前待同步草稿的四段文字，界面事先说明这一点；需要保留当前内容时应先备份。旧 v2、损坏副本及身份不符内容仍只提供查看与导出，不自动恢复为当前账号报告。

恢复前再次核对身份、会话、来源全文及当前编辑器和缓存快照。预览后来源或目标变化，需要重新预览。恢复使用来源的原版本号，不擅自改成最新版本：与当前账号版本不同时进入冲突核对；相同时进入普通待同步流程。写入本机失败不会先清空旧草稿。其他页面的来源副本始终保留，仍可导出；内存副本只有相同四段文字成功写入本机后才移除，读取账号或收到旧保存回包不会清掉它。单纯查看和导出不会触发恢复或上传。

过期只读身份、已完成会话及当前报告无法读取时不能恢复为可上传草稿，但仍可使用可读范围内的副本备份入口。

## 完成实验与跨页草稿

完成前先检查当前页面是否还有这份报告的未落盘内存正文；存在时必须先核对并将同份文字成功写入本机，单纯导出或选择完成已保存版本都不能跳过。发出完成请求前再次检查，防止同步等待期间出现新的存储失败。

随后列出本次会话的全部 v3 页面草稿，发现损坏、读取异常或清单变化时阻止归档，不当成“没有草稿”。本页待同步内容必须先保存；本页有草稿而账号缓存缺失、同步期间又有新编辑、初中事件队列损坏或补传失败，也会阻止完成。

若仍有其他标签页的有效待同步草稿，第一次点击只显示确认区。学生可回原页面保存，或先在报告页查看和导出；也可明确点击“我理解并完成已保存版本”。此选择只完成后台已经保存的版本，其他草稿留在本机，完成后不能再写入这次实验，不会自动合并或丢弃。

确认绑定当前身份、会话以及当时全部草稿的原始内容。第二次点击前、同步后再次检查；草稿发生变化需要重新确认。初中事件按指定云端活动会话补传，每批最多500条，只有当前身份且完整事件内容匹配的回包才会移除队列项。一次补传处理开始时的队列；如果期间新增或改变的事件仍留在该会话队列中，就提示重试并阻止完成，不无限追着新操作补传。高中报告不会通过初中助手队列认领数据。

这些前后核对不是跨标签页原子事务。`localStorage` 没有跨标签事务锁，另一标签仍可能在最后检查之后继续写入；本轮不承诺任意并发操作绝不会留下新草稿。服务端报告版本检查和完成后只读约束继续有效，其他页面的本机草稿继续保留。完成仍只是结束会话，不等于报告评审、教师认可或所有标签页内容都已上传。

## 高中读数进入课堂报告

教师选择已开放的高中模板、发布到自己的班级；学生从任务中心进入对应实验，工作台在核对真实会话后提供“填写课堂记录与选择读数”。报告页按当前学生归属读取本机正常档案，默认不选；选择后必须预览完整文字，再确认追加到测量字段。正文原文、读数ID、时间、条件和单位保留，手动仪器另保留原始操作读数与计数。

同一实验的自由探究记录可能也在列表中，学生应按任务明确选择。旧公共档案、待恢复副本和无法校验的手动数据不混入；本机档案存在异常时先回工作台处理。报告字数超过上限会拒绝追加，不删除原文或截断读数。确认前后重新核对身份、会话、版本与所选内容，仍由上述保存队列处理上传和冲突。

这是一份可编辑的文字副本，不是原始读数附件或不可篡改的提交凭证。后台保存后教师能查看；“完成实验”只会结束会话，不表示教师评价过结论。操作与验证见[第十四阶段验收](high-school/ACCEPTANCE_STAGE_14.md)。

## 验证与后续范围

既有接口测试覆盖 SQLite 和 PostgreSQL 适配器、角色及班级隔离、字段验证、重复保存、版本冲突与完成后只读。PostgreSQL 适配器模拟测试不等于真实 PostgreSQL 多进程验收。

本轮完整门禁已通过：1212项测试通过，1项 Linux 专用回归在 macOS 跳过；类型检查、检索评估、架构和构建检查均通过。另有15组实际前端数据模块与独立临时 SQLite 后台的真实 HTTP 联调通过，包括身份切换后的迟到回包、原操作重试、跨页版本冲突和保留原版本的明确恢复。5项只读预览检查确认现有服务提供新源码且既有数据库资源数量不变。报告路径及范围见[第十五阶段验收](ACCEPTANCE_STAGE_15.md)。

组件事件使用实际业务回调配合内存 hook/Storage 替身；下载测试验证 Blob、链接及 URL 清理的调用边界。HTTP 联调也使用内存 Storage 和注入的响应延迟；过期身份、另一后台命名空间使用本地 fixture，没有向其他后台请求。它们均未操作真实浏览器，也未启用付费 AI。

第十九阶段新增按报告版本关联的教师文字反馈，保存当时四段原文快照。教师未提交或结果待确认的反馈只留在本标签内存，按账号与完整会话归属隔离；收起、切任务或同账号续签可继续，刷新或关闭会丢失，有离开提醒。学生反馈只按需联网读取，不写入公共本机存储；读取失败不当作“没有反馈”。说明见[教师反馈与学生修订](TEACHER_FEEDBACK_DESIGN.md)。

当前报告仍是四段文字；高中可显式附入读数文字副本。仪器状态恢复、带类型与模型版本的读数附件、评分、已完成报告修订、原自由记录本迁移，以及完整修改历史尚未实现。反馈中的原文快照只覆盖被教师评阅的版本，不是每次学生保存的完整历史。真实浏览器的多标签操作、下载、刷新恢复及真实 PostgreSQL 多进程行为仍未验收；不能把缓存隔离等同于商业部署或全部并发场景已验收。

开源研究及官方来源见 [实验档案的开源设计参考](OPEN_SOURCE_LEARNING_RECORDS.md)。
