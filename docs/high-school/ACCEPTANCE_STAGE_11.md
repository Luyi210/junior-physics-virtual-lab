# 第十一阶段：高中操作草稿与失败记录恢复

日期：2026-11-11。本阶段修复已有高中工作台的操作草稿和本机保存恢复问题，不增加实验数量。第十阶段的759项测试及11项真实HTTP联调保留为独立历史记录。

## 默认条件与数值草稿

原数值控件只在已提交的 `value` 改变后同步输入。学生在默认条件下输入尚不完整的 `-` 并移开焦点，再点击“恢复默认条件”，模型值前后都相同，控件仍可能显示 `-` 和错误提示，与页面的恢复成功说明矛盾。

`HighSchoolExperimentPage.tsx` 为数值编辑器增加独立的恢复代次；仅点击“恢复默认条件”时更新代次并重新建立控件。即使已提交数值没有改变，也清除旧草稿和校验状态。普通参数修改与“重新计时”不更新该代次，避免误清其他输入。恢复默认不会清空记录仓库或重置已有的记录快照。

一次性检查以真实工作台与参数控件的TSX源码执行事件回调，用内存hook替身和实际组件key模拟实例变化，确认：

- `-` 失焦时模型仍使用原有效值，输入显示无效草稿；恢复后显示默认数值、错误清除。所有已提交参数本来就是默认值时也可恢复。
- 修改另一参数不会重建全部输入；重新计时也保留尚未提交的编辑。
- 恢复默认后传给分析面板的记录数组和记录对象未更换，仓库清空调用次数为0。

这不是浏览器或React DOM调度验收，也没有把该一次性检查计入持久测试总数。

## 双缝观察探针与读尺条件

原手动仪器用完整参数对象判定读尺草稿是否失效，包含 `screenPositionMm`。复现为A=-3.3 mm、B=3.3 mm、N=2时，将观察探针从0移至1 mm；1601个屏幕光强点逐项相同，但A/B/N及计算结果被清空。

读尺条件应由波长、缝间距和屏距决定。移动观察探针只改变当前观察点，不改变屏幕条纹，应保留本次A/B/N；真正改变条纹的条件仍需重新定位和计数。档案继续保留完整参数快照；同一次观察中，仅移动探针不应解除相同读数的重复保存限制，明确开始下一次读尺后仍可保存独立的同值观察。

单摆的 `resetToken` 继续负责重新计时后作废未完成的计时；稳态双缝不借用这个时钟信号清除读尺草稿。已保存的手动及自动记录均保留。

## 记录已满时的失败恢复

确认的复现：119条记录已落盘，第120条因浏览器存储异常写入失败。旧仓库只在新增时补写待保存记录，但此时页面和手动仓库已经达到120条新增上限。即使存储恢复，当前页仍显示120条并报错，另一个标签或刷新后只能读到119条；CSV救援存在，独立补写入口缺失。

本轮提供独立 `retryPending()`，按原编号补写本页待保存记录，不创建新的采样，也不受新增条数限制。动作仍须确认当前档案可写；读取不会自行触发补写，过期只读档案保持只读。重试需重新核对存储代次，其他标签已经清空的旧档案不能借重试恢复。

自动与手动档案在保存异常区显示“重试本机保存”，保留导出提示。操作后刷新当前快照；仍失败时保留内存记录并说明仍需导出。重试后的反馈采用当前档案条数，不在其他标签已经清空时声称旧数据已全部保存。

120条仍是交互上的新增上限，不能视为跨标签的原子容量锁。两个标签在第119条同时新增时可能保留121条唯一记录；本轮不通过截断来丢弃已经保存的记录。

收尾只读审查另确认一个尚未修复的场景：新仓库从首次访问起就完全读不到存储，已有档案实际使用非`initial`代次；此时新增的内存记录在首次读取恢复后可能被误当成旧代次数据丢弃。恢复前的失败快照尚能导出，仓库快照被替换后不再包含它。复现脚本为 `/private/tmp/physics-unknown-generation-stage11.mjs`。本阶段的补写验收限于已知代次；下一阶段需区分“尚未读取到代次”与“确知属于旧代次”，保留恢复副本，同时不能擅自把不明代次记录归入已清空后的档案。
