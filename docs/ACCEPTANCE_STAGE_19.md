# 第十九阶段：教师反馈与学生报告版本

日期：2026-11-11（Asia/Shanghai）。状态：完整质量门禁、隔离真实HTTP流程、重启保留及本地预览增量更新检查通过。真实浏览器与真实PostgreSQL并发尚未验收。

本阶段把第十八阶段的反馈方案实现到教师和学生两端。教师针对某份已保存报告的具体版本留下文字建议；学生能读取作者、时间与所评版本的四段原文，并自行修改仍在进行中的报告。已完成实验不重新开启，不绕过任务重做权限，也没有新增评分、能力排名或自动判断达标。

## 后台、版本和权限

新增`session_learning_feedback`及索引，原报告、事件、账号等表内容不作迁移或补写。契约与正文上限在`packages/contracts`；`learning-feedback.js`独立负责输入、权限、读取和追加，路由为`GET/POST /api/sessions/:sessionId/feedback`，健康能力标记`learning-feedback`。

学生只能读取自己的反馈；任课班级创建教师和同校管理员可以读取及提交。他班教师、其他学生和其他学校用户不能操作。每次新写通过一条条件INSERT同时核对真实作者、当前学校/班级/任务/学生归属和期望报告版本，直接从报告表复制四段全文；不接受客户端快照，也不使用跨多个await的SQLite共享连接事务。反馈保留作者当时的姓名和角色、所评报告版本/更新时间、正文及创建时间。

正文保留空格、换行与合法Unicode，不接受全空白、超过4000个JavaScript字符串长度单位、NUL或不成对代理项。版本必须为至少1的安全整数。相同作者、会话、操作编号对应相同正文与版本时返回原反馈；即使学生后来已保存新报告，相同重试仍成功。不同正文或版本复用编号返回`FEEDBACK_CONFLICT`；新操作基于已过期报告返回`RECORD_CONFLICT`，没有已保存报告则返回`RECORD_REQUIRED`。

反馈不更新学生报告版本或会话状态。已完成、已关闭或不可重做任务的已有报告可继续收到反馈，学生原报告仍只读。单条写入的快照与修订一致性已用SQLite和pg-mem验证；pg-mem不证明真实PostgreSQL MVCC或多进程行为。

## 教师与学生页面

教师明确打开某份学生档案中的反馈面板才请求历史。依据版本和四段原文单独显示；版本冲突保留草稿，刷新报告后需要明确点击“已重新核对，改用此版本”，再提交反馈。最近已读取账号版本与实际选择的反馈依据分开管理。网络结果不明时锁定原正文、版本与操作编号，重试同一操作；成功只清理匹配的待确认草稿。

教师草稿仅保存在当前标签模块内存，按固定教师通道、后台、学校及完整会话归属隔离。收起、切任务、续签或回到同账号可继续；其他账号不显示原稿。关闭或刷新标签会丢失，有离开提醒但不保证浏览器一定显示。没有持久云草稿或任意多个同会话面板共享写入协议。生成安全随机操作编号不可用时保留文字、显示错误并阻止发送。

学生按需联网读取反馈，失败时明确显示未读成功，不当作空列表。反馈只放本页内存，不写入公共本机存储，不调用原报告的remember、queue、sync或完成接口。整批响应核对身份、会话、版本与字段形状；旧账号、续签、到期、旧路由及卸载后的响应不能显示。当前账号报告与未同步本机文字分别说明；反馈关联版本比本页记录更新时，提示重新读取报告。

共用原文展示组件放在`features/learning-feedback/`，教师操作留在`features/teacher/`，学生阅读留在`features/student/components/`，API客户端仍在`data/`。原文展开、旧按钮及异步回调检查当前身份与完整会话归属。React转义显示全文，不将教师或学生文字作为HTML执行。
