# 开源教学智能体与物理仿真的本项目适配方案

核对日期：2026-11-22。依据当前工作区源码和[开源学习清单](OPEN_SOURCE_AGENT_SIMULATION_REVIEW_2026_11_22.md)。本页是下一阶段实施方案；未引入第三方运行依赖，也未把下述待做项当作已上线功能。已接入的教学图与本页计划中的现场证据适配，是两个不同的进度阶段。

## 现有链路与接入点

| 层次 | 已有入口 | 适配动作 |
| --- | --- | --- |
| 物理真值 | `packages/physics/src/`；高中统一使用 `simulateHighSchoolExperiment`，初中凸透镜使用 `calculateLens` | 数值、有效范围、警告由模型或经过模型复算的记录给出。动画、讲解、题目映射共用相同参数定义。 |
| 初中现场 | `apps/web/src/features/assistant/tutorialBridge.ts` 的装置快照；`harnessStore.ts` 的事件和观察 | 在提问时将**当前实验的**快照、最近操作和观察转成有来源的结构化证据，传入教学图。现有规则回复仍可用。 |
| 高中现场 | `apps/web/src/data/highSchoolContext.ts` 的参数、时刻、自动采样、手动读数；`packages/harness/src/highSchool/lili.ts` 的模型复算与提示 | 在提问时构造同一份证据摘要，并保留当前已有的安全边界、记录来源区分和模型约束检查。若需要判断操作顺序，再新增有限的事件记录。 |
| 教学决策 | `packages/harness/src/agent/tutorGraph.ts`；`packages/harness/src/coach.ts`；高中力力规则 | 借鉴 OATutor 的概念与分级提示、H5P 的数据化分支，把“观察证据→误解判断→下一步操作→复核条件”写成可测试的实验教学条目。 |
| 前端呈现 | `AssistantPanel.tsx`、`LiliAssistant.tsx` 的对话、提示梯、动作按钮 | 每轮展示“依据：当前条件／已保存虚拟读数／模型预测／学生自述”及一个可执行动作；证据不足时明确请学生先操作或记录。 |
| 后端与持久化 | `apps/api/`、本地会话和学习记忆存储 | 先沿用现有鉴权、会话和可选 AI 服务；只有出现跨设备恢复、多步工具或教师审核需求时，再试 LangGraphJS 等服务端编排。 |

## 优先解决的接缝

1. **把可用证据送进教学图。** 目前初中调用 `runPhysicsTutorAgent` 时只给实验 ID、问题、记忆、掌握度和“是否有观察”；高中只给实验 ID、问题、记忆、掌握度和“是否有手动记录”。两端的原有规则引擎可以使用更多上下文，但新的教学图没完整收到。建立小型 `TutorEvidence` 输入：`experimentId`、`parameters`、`modelReadings`、`savedVirtualReadings`、`studentObservations`、`recentActions`、`warnings`、`capturedAt`，每项保留来源、单位和时刻，缺失就不填。它是提问时的快照，不能用原地更新的实时对象替换旧回复依据。
2. **让分支条件基于证据。** 每个教学条目声明 `prerequisites`、`misconceptionEvidence`、`hint1/2/3`、`verifyAction`、`verifyEvidence`。只有符合条件才说“发现了某问题”；没有记录时给采集步骤，不能说学生已完成实验。提示级数由学生主动请求或可验证的现场进展控制，不根据聊天轮数推断掌握。
3. **让物理核验可测试。** 现有教学图中的 `physics_guardrail` 主要替换两种措辞，不能称为物理正确性验证。把数值主张改为结构化 `claim`，先由 `packages/physics/` 复算，再检查单位、模型适用范围及证据来源；复算不了就说“不足以判断”。保留高中已实现的手动读数与自动模型采样分离逻辑。
4. **让学习状态谨慎更新。** 当前 BKT 由自测选项的正误更新；继续限定在明确知识点的自测，不把点击提示、自动仿真数值或一次开放操作当作“已掌握”。“掌握度”界面宜标注为基于有限自测的练习估计。

## 三项样板实验

| 实验 | 可验证的现场分支 | 给学生的下一步 | 完成条件 |
| --- | --- | --- | --- |
| 初中凸透镜 | 物距是否跨过 `f`/`2f`；光屏是否在模型像距附近；虚像时是否试图在光屏接像 | 先预测像的性质，再只移动物体或光屏一项，观察清晰度和像的方向 | 依据当前焦距、物距、屏距解释成像；指出虚像不可由光屏承接，且不把模型值称为实测 |
| 初中欧姆定律 | 电路是否接齐；是否先大量程试触；有无至少三组不同自变量且控制量相同的正式读数 | 先修正接法或量程，再仅改变 `U` 或 `R` 并保存一组读数 | 用保存的 `U/I/R` 记录核查正比或反比；数据不足时不下结论 |
| 高中单摆 | 摆角是否符合小角度近似；是否保存两组不同摆长、其余条件相同的读数；是否有手动计时 | 先预测 `T²` 与 `L` 的关系，再做对照记录；大摆角时解释近似边界 | 区分精确模型周期、学生的虚拟手动计时和现实测量；只比较同条件、同来源的记录 |

## 实施顺序与验收

1. 在 `packages/harness/` 定义通用证据契约和三项教学条目；在初高中前端各做一个只读适配器。先复用已有快照与保存记录，不复制开源项目的代码或图像。
2. 在 `tutorGraph.ts` 增加按证据路由的节点，保留原规则回复作为未覆盖实验的回退；动作按钮仍需经过现有参数校验和档案权限检查。两个助手共用判据，文案和实验上下文各自保留。
3. 为每项样板覆盖四类验收：正确操作、典型误操作、数据不足、超出模型范围。还要验证切换实验／身份后旧回复不引用新条件、离线仍能获得本地提示、手机端按钮和证据标签可读。
4. 用真实学生试用记录“是否能独立完成下一步”和“是否误把模型值当实测”。在此之前，不用规则测试通过宣称教学效果或任意题目理解能力。

## 开源项目如何用

- [OATutor](https://github.com/CAHLR/OATutor)：借鉴“知识点—练习—逐级提示—尝试记录”；本项目的开放实验仍以操作证据为主。
- [H5P Branching Scenario](https://github.com/h5p/h5p-branching-scenario)：借鉴可编辑的分支内容结构；先用本项目已有 React 页面呈现，不接入整套 H5P 运行时。
- [myPhysicsLab](https://github.com/myphysicslab/myphysicslab)：借鉴模型、视图、图表分层；新实验先在 `packages/physics/` 建模和测试，再连到画面。
- [LangGraphJS](https://github.com/langchain-ai/langgraphjs)：以后服务端确有检查点恢复和人工审核需求时再选型；现有同步教学图先保持轻量。

公开网站的代码版本以 GitHub Pages 部署结果为准；后端学习记忆接口需要单独部署 API 服务，不能仅靠静态网站启用。
