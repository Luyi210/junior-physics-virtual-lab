日期：2026-11-11（Asia/Shanghai）。本阶段修复第十六阶段发现的后台启动问题，保留全部既有教学数据。高中仍为8项开放、16项筹备；本阶段不新增实验。

## 产品行为

1. 已有学校与完整账号身份时，只执行需要的结构迁移并继续使用现库。演示开关和 bootstrap 配置不会重置账号、改密码、启用停用用户、增建学校或恢复已删除的演示内容。代码新增的演示课例也不会自动补入已有库。
2. 空SQLite开发库可一次性初始化演示；空正式SQLite和PostgreSQL需要有效的首次管理员配置。PostgreSQL默认关闭演示，空PG显式开启演示会拒绝启动，不再生成空邮箱管理员。
3. 只有学校、没有管理员、用户学校归属缺失、无效管理员身份或空学校/用户标识的库会拒绝启动，保留原状供人工核对。包括SQLite允许出现的NULL文本主键，以及空串、制表符、Unicode空白身份标识。
4. SQLite在初始化事务中完成建表、迁移、锁内判断和整批写入，失败回滚并关闭连接。WAL设置与 `BEGIN IMMEDIATE` 共用约5秒的锁竞争期限；只重试busy错误。PostgreSQL使用同一client内的事务与advisory锁；借用pool由调用方管理，回滚失败的client会被丢弃。
5. 运行时只在数据库初始化完成后启动服务，监听成功后报告实际的 `existing`、`demo` 或 `bootstrap` 结果。启动失败会尝试清理已创建的助手、检索和数据库资源。日志不打印密码、哈希或令牌密钥；正式首次日志仍包含管理员邮箱。
6. 修复初始化与登录输入的差异：254字符的管理员邮箱可以登录；登录、创建和重置密码保留原始首尾空白，并拒绝全空白或超过200字符的密码。旧哈希不自动修改，旧版去空白后保存的密码仍以实际保存值登录。

实现入口：[共享初始化策略](../../apps/api/src/database-initialization.js)、[SQLite适配器](../../apps/api/src/database.js)、[PostgreSQL适配器](../../apps/api/src/database-postgres.js)、[服务生命周期](../../apps/api/src/server-runtime.js)、[启动入口](../../apps/api/src/server.js)。配置和运行说明见[API文档](../../apps/api/README.md#首次初始化与普通重启)。
