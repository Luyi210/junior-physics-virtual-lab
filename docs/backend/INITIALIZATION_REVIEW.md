# 后台初始化与重启审查

日期：2026-11-11。下方“已确认行为”保留第十六阶段的修复前审查证据。第十七阶段已在产品启动流程中实现首次初始化与普通重启分离，当前规则见[API说明](../../apps/api/README.md#首次初始化与普通重启)，具体自动与HTTP证据见[第十七阶段验收](ACCEPTANCE_STAGE_17.md)。

## 已确认行为

1. 修复前，SQLite演示seed在每次打开库时执行。`apps/api/src/database.js`的学生插入语句使用`ON CONFLICT(id) DO UPDATE`，覆盖10名已有演示学生的邮箱、密码哈希和姓名。通过正常管理接口修改后，重启会改回预设值；停用状态未被这条语句改动，管理员和教师采用只插入缺失记录的方式。审查最初考虑只补缺失记录，最终实现进一步明确为现有数据库完全不补种，避免恢复用户已删除的演示内容。
2. `seedDemoData=false`时，`apps/api/src/server.js`在打开库前要求bootstrap邮箱及至少12字符密码，即使已有可用账号也如此。SQLite与PostgreSQL初始化都会尝试插入`school-primary`；已有演示库切换此模式时会增建学校，但固定管理员ID冲突可能使管理员创建被忽略，日志却仍显示配置邮箱。应区分首次初始化与普通重启，依据数据库真实状态执行原子初始化，并报告实际结果。
3. PostgreSQL适配器目前不实现SQLite演示seed，始终走bootstrap。非生产环境默认`seedDemoData=true`且bootstrap凭据为空时，server的false分支校验被跳过，PG空库可能写入空邮箱/空密码哈希管理员并打印不存在的演示教师提示。正常登录的非空输入校验阻止该空账号登录，但库已落入不完整状态。应明确拒绝不支持的演示组合，或实现一致的演示策略；不能静默转为空凭据bootstrap。

证据位置：`apps/api/src/server.js`启动前检查与日志，`apps/api/src/database.js`的`seed`/打开库流程，`apps/api/src/database-postgres.js`的bootstrap/打开库流程，`apps/api/src/config.js`的演示和初始管理员默认值。行号会随修复变化，以函数与实际语句为准。

## 最小修复与验证要求

- 保留所有现有账号、密码、停用状态、学校归属和课堂内容，不以恢复默认数据解决初始化差异；不修改已有预览数据库作为回归fixture。
- 临时文件SQLite：首次初始化12个演示账号；修改学生邮箱、姓名、密码和状态；关闭重开后完整保留；缺失演示账号的补齐规则明确。
- 分别覆盖空库、已有正式库、已有演示库、只有部分学校/用户的库，以及重复或并行初始化。普通重启不要求保存或再次提供最初的bootstrap密码，不增建无关学校。
- PostgreSQL的`seedDemo=true/false × 空库/已有库`行为明确且有测试；凭据或策略无效时不得先写入无用的学校/管理员。
- 日志只报告实际初始化结果，不打印密码或令牌，也不把配置值当成创建成功的证明。
- API及课堂回归保持通过。pg-mem用于逻辑回归，真实PostgreSQL连接、事务与并发启动仍需要独立验收。

## 第十七阶段的实现结论

- 两种适配器均在初始化锁内读取现状，只有没有学校和用户的空库执行首次初始化。已有完整账号库直接返回 `existing`，不会重新应用 bootstrap 或演示数据。停用管理员仍保持停用，完整性判定不承诺密码可登录。
- 学校或用户缺失、孤立用户、空邮箱或空哈希管理员、空或纯空白身份标识会中止启动，保留业务数据；不会自动修复、提升权限或新增替代管理员。
- SQLite 使用 `BEGIN IMMEDIATE` 包含建表、迁移、判断与整批写入；WAL切换和取得事务锁共享约5秒的锁竞争等待期限。只重试 `SQLITE_BUSY`，其他失败直接传播，回滚后关闭连接。
- PostgreSQL 使用专用 client 中的事务级 advisory lock；首次学校和管理员使用严格 INSERT。回滚失败会销毁该 client，保留原始启动错误；调用方注入的 pool 始终由调用方管理。真实PG并发与回滚仍待验。
- `server-runtime.js` 只在数据库完成后启动检索、助手和 HTTP，按实际初始化结果输出脱敏日志；启动失败尝试释放已经取得的全部服务与连接。
- 配置默认值改为开发SQLite空库启用演示，生产或PostgreSQL默认关闭演示。空PG显式请求演示会拒绝启动，不再写入空管理员。
- 联调发现并修复了凭据不一致：最长254字符的初始化邮箱现在可登录；登录、创建和重置密码保留输入首尾空白，拒绝全空白或超长密码。已有哈希不变。

官方事务与测试替身的依据见[初始化参考说明](INITIALIZATION_REFERENCES.md)。既有数据库不因新增演示课例自动升级；后续课程或数据迁移仍须有明确方案和独立验收。
