# 第四十三阶段：子域名部署准备

日期：2026-11-12（Asia/Shanghai）。用户选择 `physics.xianghuiacademy.cn` 作为物理平台专用子域名。本阶段仅完成本地配置、发布包和部署前核查；物理平台没有上传、安装、启动或公开。

## 已确认

- 主域名 `xianghuiacademy.cn` 的 A 记录指向现有腾讯云服务器，DNS 使用 DNSPod；本轮查询时 `physics.xianghuiacademy.cn` 没有 A 记录。
- 腾讯云控制台可见主域名已有正常的 ICP 网站记录，但备案的网站名称属于另一产品。腾讯云说明已在腾讯云备案的主域下子域名通常无需单独备案；独立物理平台是否需要变更已有网站信息，仍应核实原填报内容及当地要求。[腾讯云备案场景](https://cloud.tencent.com/document/product/243/19630)、[备案信息变更](https://cloud.tencent.com/document/product/243/73180)。
- 控制台可见目标轻量服务器防火墙开放 22、80 和 ICMP，未见 443 规则。先前只读检查显示 Node 24、Nginx 和既有产品服务运行，候选 18080/18787 端口当时没有监听；这些服务器内部信息在实际安装前必须刷新。
- 后续用户在同一实例执行 `ss -ltn` 并提供结果：`0.0.0.0:80` 与 `0.0.0.0:443` 正在监听，候选 `18080`/`18787` 未出现在监听列表。该结果仅证明检查瞬间没有监听，不能证明端口已预留、监听进程身份或 Nginx 站点配置；启动前仍须复核。
- 随后用户提供经 `nginx -T` 过滤的只读配置：已有 `listen 80 default_server`、`listen 443 ssl default_server`；相辉主域和 `www` 分别有站点，现有代理目标为 `127.0.0.1:3100` / `127.0.0.1:3103`，另有本机 `127.0.0.1:8080`。结果中没有 `physics.xianghuiacademy.cn`。因此在新站点实际安装前，不能先将物理子域名公开解析到该主机，否则未匹配的请求可能落到相辉默认站点；新站点必须使用独立 `server_name`，不修改默认站点及既有代理，并在 `nginx -t` 后做 Host/SNI 定向验收。
- 随后用户在同一实例确认 `node` 实际路径为 `/opt/node-v24.22.2-linux-x64/bin/node`，版本 `v24.22.2`；根分区可用 26G（40G 总量、已用 13G）；`/srv/physics-lab` 不存在。已将物理服务模板的两处 Node 可执行路径对齐到这一实际路径。安装时仍须复核该文件可执行、架构与版本，且该路径属于主机现有运行时，不改变相辉产品的 Node 安装或服务。
