# 代码导览：从哪里开始看

这份导览用于第一次阅读 V2 主工程。完整的模块边界与开发约定见[代码架构说明](CODE_ARCHITECTURE.md)。

## 先区分源码与生成文件

| 位置 | 内容 | 阅读建议 |
| --- | --- | --- |
| `apps/web/src/` | 网页页面、实验交互、二维和三维画面 | 想改界面时从这里开始 |
| `apps/api/src/` | 账号、班级、记录、知识检索与助手接口 | 想改后台时从这里开始 |
| `packages/physics/src/` | 初高中物理计算与边界测试 | 想核对公式和数值时先看这里 |
| `packages/harness/src/` | 光光、力力的规则与教学判断 | 想改实验辅导时看这里 |
| `packages/knowledge/src/` | 教材目录、知识和课程映射 | 想改实验名称、教材对应时看这里 |
| `packages/contracts/` | 网页与后台共用的数据类型 | 想改接口字段时核对这里 |
| `scripts/`、`deploy/` | 开发检查、构建、启停与部署 | 改运行方式时看这里 |
| `docs/` | 设计、验收和部署说明 | 阅读资料，不是运行代码 |

`package-lock.json` 很大是正常的：它由 npm 生成，用来锁定依赖版本；日常不在里面找产品功能，也不要手工整理其内容。`node_modules/`、`dist/`、`.runtime/` 分别是安装依赖、构建输出和本机运行产物，不是功能源码。

## 读一个实验的顺序

1. 在 `packages/knowledge/` 找课程名称与实验编号。
2. 在 `packages/physics/` 看输入参数、计算和适用条件。
3. 在 `apps/web/src/features/` 找对应实验的操作和画面。
4. 在同目录的 `*.test.ts(x)` 看已覆盖的数值与交互边界。
5. 有账号、课堂或保存需求时，再看 `apps/web/src/data/`、`apps/api/src/` 与 `packages/contracts/`。

源码按功能放置，测试通常跟在被测模块旁边。更多设计资料见[项目文档导航](README.md)。需要进一步核对哪些内容已经发布、哪些只是本机改动时，查看 `git status` 和 GitHub Actions 发布记录。
